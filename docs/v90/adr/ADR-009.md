# ADR-009: Küratörlü video manifesti, resmi embed player, oEmbed doğrulama scripti; yeniden host yok

- **Durum:** Kabul edildi
- **Tarih:** 2026-09-03
- **İlgili gereksinimler:** R114.1, R114.2, R114.3, R114.4, R114.5, R115.1, R115.2, R115.3; dolaylı: R117.1, R117.4, R118.1; kabul senaryoları AT-17, AT-18

## Bağlam

- Her hareketin sayfasında teknik video gösterilir. Spec §114, video URL'lerinin runtime'da arama sonuçlarından çekilmesini (R114.1) ve videonun indirilip yeniden host edilmesini (R114.5) **yasaklar**; kaldırılmış videoda çökme olmamasını (R114.3) ve çalışan bir fallback'i (R114.4) zorunlu kılar. §115 bir geliştirme aracı ister: `npm run verify:exercise-videos`, bozuk videoları raporlar, build'i zorunlu bloklamaz (R115.1–R115.3).
- V90 **offline-first** ve **sunucusuz**dur (02 §1, §2.2). Video, ağ gerektiren tek core-dışı özelliktir; `NetInfo` yalnızca video bileşenine bilgi verir. Core workout akışı (set loglama, rest timer, substitution) videoya bağımlı olamaz (AT-18).
- 02 §14'te tanımlı bileşenler: `data/exercise-videos.json` (manifest), `ExerciseVideo` (`react-native-youtube-iframe`, resmi IFrame Player API, WebView), `VideoFallback`, `scripts/verify-exercise-videos.ts` ve `core/media/VideoManifest`. 02 §8.1'de `Exercise.video?: VideoRef` "manifest'ten" gelir; `cues: string[]` (03: `exercises.cues_json`) fallback metnidir.
- 03'te `exercises` tablosunda video kolonu **yoktur**: video bilgisi kullanıcı verisi değildir, bundle içindeki manifest'te yaşar; `TableRegistry`/backup kapsamı dışındadır (R95.1 etkilenmez).
- Hukuki çerçeve: YouTube Hizmet Şartları içeriğin indirilmesini ve yeniden dağıtımını yasaklar; IFrame Player API ve `youtube.com/oembed` uç noktası resmi, API anahtarı gerektirmeyen yollardır.
- Ürün riski: yanlış teknik gösteren, kanalı değişmiş ya da kaldırılmış videolar. Küratörlük insan işidir; geçerlilik denetimi otomasyon işidir.

## Karar

1. **Manifest tek kaynaktır.** `data/exercise-videos.json`, anahtarı `exercises.id` (slug, örn. `lat-pulldown`) olan bir sözlüktür; değer `VideoRef`:

   ```ts
   const VideoRef = z.object({
     videoProvider: z.literal('youtube'),                       // v1'de tek provider; union genişletilebilir
     videoId: z.string().regex(/^[A-Za-z0-9_-]{11}$/),
     channelName: z.string().min(1),
     sourceUrl: z.string().url(),                                // kanonik watch URL
     lastVerifiedAt: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
     fallbackUrl: z.string().url().nullable().optional(),
   }).refine(v => v.sourceUrl.includes(`v=${v.videoId}`) || v.sourceUrl.endsWith(`/${v.videoId}`),
             'sourceUrl ile videoId uyuşmuyor');
   ```

   `core/media/VideoManifest` manifest'i bundle'dan yükler ve `z.record(ExerciseId, VideoRef)` ile doğrular; doğrulama **test zamanında** koşar (hatalı kayıt = CI hatası), runtime'da yalnızca tip güvenli okuma yapılır. Manifest'te kaydı olmayan hareket "video yok" durumudur, hata değildir → doğrudan `VideoFallback`. Runtime'da hiçbir arama, keşif veya URL üretimi yoktur (R114.1, R114.2).

2. **Oynatıcı yalnızca resmi embed player'dır.** `ExerciseVideo` bileşeni `react-native-youtube-iframe` (IFrame Player API, `react-native-webview` üzerinde) kullanır ve şu sözleşmeye uyar:
   - `NetInfo` çevrimdışı diyorsa WebView **hiç mount edilmez**, doğrudan `VideoFallback` gösterilir.
   - `onError` gelirse **veya** 8 s içinde `onReady` gelmezse `VideoFallback`'e geçilir; hata `VideoUnavailable` sınıfına düşer (02 §15) ve hiçbir zaman `ErrorBoundary`'ye yükselmez (R114.3, R117.1, R117.4).
   - Otomatik oynatma yoktur (`play={false}`); WebView yalnızca kullanıcı exercise sayfasını açınca yüklenir. Kullanıcı verisi WebView'a geçmez (R118.1 ruhu).
   - Bileşen, paket değişirse kırılmamak için `VideoPlayerPort { load(videoId); onReady; onError }` soyutlamasının arkasındadır.

3. **Fallback her zaman çalışır.** `VideoFallback` üç parçadan oluşur: (a) thumbnail `https://i.ytimg.com/vi/<videoId>/hqdefault.jpg` — best-effort, yüklenemezse statik placeholder; (b) `cues[]` teknik ipuçları — bundle'da, her zaman çevrimdışı; (c) **"Kaynağa git"** linki — `fallbackUrl ?? sourceUrl`, `Linking.openURL`. Exercise sayfasının geri kalanı (set loglama, geçmiş, "Hareketi Değiştir") videodan bağımsız render edilir (R114.4).

4. **Yeniden host yok.** Video dosyası indirilmez, disk/bellek önbelleğine alınmaz, bundle'a konmaz, kendi CDN'e kopyalanmaz. Bundle'da yalnızca manifest metadata'sı ve `cues` bulunur. Bağımlılık allowlist'i `ytdl`, `youtube-dl`, `yt-dlp` türevi paketleri reddeder (R114.5).

5. **Doğrulama scripti dev-time çalışır.** `scripts/verify-exercise-videos.ts` (`npm run verify:exercise-videos`), manifest'teki her kayıt için `https://www.youtube.com/oembed?url=<sourceUrl>&format=json` isteği yapar ve sınıflandırır:

   | Yanıt | Sonuç |
   |-------|-------|
   | 200, `author_name == channelName` | `OK` |
   | 200, `author_name != channelName` | `CHANNEL_MISMATCH` (uyarı; kanal adı değişmiş veya video başka kanala taşınmış) |
   | 401 / 403 / 404 | `BROKEN` (gizli, embed kapalı, kaldırılmış) |
   | ağ hatası / timeout | `UNKNOWN` (1 kez yeniden denenir; `BROKEN` sayılmaz) |

   Rapor: tablo + `--json`. Varsayılan exit 0 (R115.3); `--strict` ile `BROKEN` varsa non-zero. CI: PR'da uyarı olarak koşar, haftalık cron `--strict` ile issue açar. `--write` ile `OK` kayıtların `lastVerifiedAt` alanı günün tarihiyle güncellenir ve değişiklik PR olarak gelir (02'de belirtilmemişti; bu ADR ile netleştirildi). Script API anahtarı gerektirmez; opsiyonel `--deep` modu, yalnızca CI secret'ındaki anahtarla Data API `videos.list?part=status` üzerinden `embeddable=false` durumunu da yakalar.

6. **Küratörlük süreci.** Yeni video = manifest PR + `verify:exercise-videos` yeşil + inceleme checklist'i (doğru hareket, doğru teknik, embed izinli, kanal güvenilir, mümkünse Türkçe altyazı). Her hareketin `cues_json`'u en az 3 ipucu içerir ki fallback boş kalmasın.

## Değerlendirilen alternatifler (en az 2; her biri için neden reddedildi)

| Alternatif | Neden reddedildi |
|------------|------------------|
| **A. Runtime YouTube Data API araması** (`search.list` ile "<hareket> form") | R114.1 açıkça yasak. Kalite kontrolsüz; API anahtarı bundle'da sızar ve kota tükenir; offline'da kırık; sonuçlar zamanla değişir → deterministik olmayan UX. |
| **B. Videoları indirip re-host etmek** (kendi CDN'i veya app asset'i) | R114.5 yasak; YouTube ToS ve telif ihlali. "Sunucu yok" ilkesine (02 §1) aykırı; bundle'a koymak 50+ video × ~20 MB; içerik güncellemesi app release gerektirir. |
| **C. Ekibin kendi çektiği videolar** | v1 için reddedildi: üretim maliyeti/süresi; yine hosting sorunu (B). Mimari kapı açık: `videoProvider` union'ına `'self'` eklenebilir, ama o zaman da resmi/kontrollü bir player ve CDN gerekir. |
| **D. Üçüncü taraf egzersiz video API'si** (ExerciseDB, wger vb.) | Ağ bağımlılığı core sayfaya sızar; lisans belirsiz; Türkçe içerik yok; teknik kalite kontrolü dışarıda. |
| **E. Embed yerine YouTube uygulamasına / tarayıcıya deep link** | Yalnızca fallback'teki "Kaynağa git" olarak kabul edildi. Ana yol olarak reddedildi: kullanıcı uygulamadan çıkar, aktif antrenman ekranı ve rest timer görünümü kaybolur. |
| **F. Runtime'da oEmbed ile doğrulama** (uygulama açılışında tüm manifest) | Offline'da anlamsız; her açılışta onlarca ağ isteği (pil, gizlilik); `onError` + fallback runtime'ı zaten kapsıyor. Doğrulama dev-time/CI işidir (R115). |

## Sonuçlar (olumlu / olumsuz / riskler ve azaltımlar)

**Olumlu**
- Video kalitesi insan tarafından kontrol edilir; davranış deterministiktir (aynı hareket → aynı video).
- Hukuki risk düşük; sunucu/CDN maliyeti sıfır; API anahtarı yok.
- Exercise sayfası çevrimdışı ve video kaldırılmışken de tam çalışır (`cues`, kaynak linki).
- Bozuk videolar kullanıcı görmeden CI raporunda yakalanır.

**Olumsuz**
- Video izlemek ağ gerektirir; YouTube reklam ve branding'i gösterilir.
- Manifest bakımı manuel emektir; küratör darboğazı oluşabilir.
- Thumbnail dış kaynaktır; kaldırılmış videoda gri placeholder döner — R114.4'teki "thumbnail çalışmaya devam eder" ancak best-effort sağlanır.

**Riskler ve azaltımlar**

| Risk | Azaltım |
|------|---------|
| oEmbed 200 döndürür ama video embed'e kapalıdır (`embeddable=false`) | Runtime'da `onError` → fallback; CI'da opsiyonel `--deep` modu. |
| YouTube IFrame API veya `react-native-youtube-iframe` kırılır | Tüm hareketler aynı anda fallback'e düşer, uygulama çalışmaya devam eder (R114.3); `VideoPlayerPort` soyutlaması paket değişimini yerelleştirir. |
| Thumbnail için `i.ytimg.com` isteği izinsiz "ağ trafiği" sayılabilir | Yalnızca video ekranında ve yalnızca kullanıcı açınca; `cues` ile birlikte statik hareket illüstrasyonu (bundle asset) gösterilebilir. Thumbnail önbelleği bilinçli olarak yoktur (yeniden host çizgisine yaklaşmamak için). |
| Kanal adı değişince manifest yanlış görünür | `CHANNEL_MISMATCH` yalnızca uyarıdır; `--write` ile düzeltme PR'ı. |
| Manifest ile katalog ayrışır (yetim kayıt) | Test: manifest anahtarları ⊆ `data/exercises.json` id'leri. |

## Doğrulama (hangi test/kabul senaryosu bu kararı doğrular)

- **AT-17** (E2E, Maestro): geçersiz `videoId` içeren test manifest fixture'ı ile exercise sayfası açılır → `VideoFallback` görünür, `cues` listelenir, "Kaynağa git" tıklanabilir, set loglanabilir; beyaz ekran yok.
- **AT-18** (E2E): uçak modu → exercise sayfası WebView mount edilmeden fallback ile açılır; core workout özellikleri çalışır.
- **Unit — `VideoManifest`:** eksik alan, geçersiz `videoId`, `sourceUrl`–`videoId` uyuşmazlığı → Zod hatası; manifest anahtarları ⊆ katalog id'leri; her katalog hareketinin `cues_json` ≥ 3 ipucu.
- **Component (RNTL) — `ExerciseVideo`:** `onError` → fallback; 8 s `onReady` timeout (fake timers) → fallback; `NetInfo` offline → WebView hiç render edilmez; `play={false}`.
- **Script testi** (02 §17, §115 satırı): oEmbed mock ile 200 / 200+`author_name` farklı / 401 / 403 / 404 / timeout → `OK` / `CHANNEL_MISMATCH` / `BROKEN` / `UNKNOWN`; `--strict` exit code; `--json` çıktısı şeması; `--write` yalnızca `OK` kayıtların `lastVerifiedAt`'ini değiştirir, diğer alanlara dokunmaz.
- **Statik/CI:** repo'da video dosyası (`.mp4`, `.webm`, `.mov`) bulunmadığını doğrulayan kontrol; bağımlılık allowlist'i (`ytdl`/`youtube-dl` türevleri yasak); `verify:exercise-videos` PR'da uyarı, haftalık cron `--strict`.
