# ADR-011: Hacim analitiğinde yalnızca direct set sayılır; secondary katkı ayrı tahmindir; unilateral çift sayılmaz

- **Durum:** Kabul edildi
- **Tarih:** 2026-09-03
- **İlgili gereksinimler:** R102.1, R102.2, R102.3, R102.4, R106.1, R106.2, R106.3, R106.4, R123.4; dolaylı: R103.4, R103.5, R105.2, R105.3, R107.2; kabul senaryoları AT-06 (dolaylı), birim/integration testleri (02 §17: §102 ve §106 satırları)

## Bağlam

- **Weekly Sets by Muscle** (R106.1) Progress ekranının ana hacim metriğidir ve `VolumeGuardrails` için `currentWeeklySets` girdisidir (R105.2). Analitikteki bir sayım hatası doğrudan öneri hatasına dönüşür.
- Spec: ana görünüm direct/primary working set'lerdir (R106.2); compound hareketlerin dolaylı katkısı "1 tam set" kesinliğiyle toplanamaz (R106.3); secondary katkı istenirse ayrı bir analitik olarak ve tahmin olduğu belirtilerek gösterilir (R106.4, R123.4); unilateral setler çift sayılmaz — sol+sağ = 1 set (R102.4).
- Literatürde "set" sayımı tartışmalıdır: indirect katkı için 0.5 katsayısı yaygın ama kanıtı zayıftır. Spec bu belirsizliği "ayrı ve etiketli tahmin" olarak çözer.
- Unilateral hareketlerde 02 §7.4: `session_exercises.tracking_mode ∈ {'bothSame','separate'}`; `separate` modunda aynı `set_index` için iki `set_logs` satırı (`side='left'` / `'right'`), `bothSame` modunda tek satır `side='both'`. Naif `COUNT(*)` `separate` modunu iki kat sayar.
- 02 §9.4: `VolumeAnalytics.weekly(weekKey)` → `{ muscle, directSets, secondarySetsEstimate }`; `secondarySetsEstimate = 0.5 × secondary working set sayısı`. 03 §1.10: `v_weekly_direct_sets` görünümü, `COUNT(DISTINCT s.session_exercise_id || ':' || s.set_index)`, filtre `set_type = 'working' AND discarded = 0 AND ws.status IN ('completed','partial')`, `GROUP BY ws.calendar_date_key, e.primary_muscle`.
- 03 `exercises`: `primary_muscle`, `secondary_muscles_json` (JSON kolon), `is_unilateral`, `volume_multiplier REAL DEFAULT 1`; 03 §3 `MuscleGroup` union (`lats` ve `upperBack` ayrı). 02 §8.1 `volumeMultiplier: 1` "unilateral çift sayım koruması".
- Substitution sonrası set kaydı yapılan hareketin `exercise_id`'siyle yazılır; `original_exercise_id` yalnızca geçmiş bağlamıdır (R99.5, R99.7).

## Karar

1. **Analitik birimi "direct set"tir** (02 §4 sözlük). Bir `set_logs` satırı direct set sayılır ancak ve ancak: `set_type = 'working'`, `discarded = 0`, oturum `workout_sessions.status IN ('completed','partial')` ve hedef kas = **yapılan** hareketin (`set_logs.exercise_id`) `exercises.primary_muscle` değeriyse. `warmup` sayılmaz (R107.2 ile tutarlı); `dropset` ve `backoff` v1'de set sayımına girmez (ileride ayrı metrik; 02/03 bunları tanımlamıyor).

2. **Tek kaynak SQL: `v_weekly_direct_sets`.** Sayım ifadesi `COUNT(DISTINCT session_exercise_id || ':' || set_index)`'tir; böylece `separate` modundaki left/right satırları ve farklı oturum/hareketlerde çakışan `set_index` değerleri doğru ele alınır. `VolumeAnalytics.weekly(weekKey)` bu görünümü `calendar_date_key` ile hafta aralığına toplar; `VolumeGuardrails.currentWeeklySets` ve Day 90 raporu **aynı fonksiyondan** okur (kopya sorgu yasak).
   - **Hafta tanımı:** Pazartesi başlangıçlı yerel takvim haftası; `weekKey` = haftanın Pazartesi gününün `YYYY-MM-DD` anahtarı. `AdherenceCalculator.week(weekStartKey)` ile aynı anahtar kullanılır (02/03'te tanımsızdı; bu ADR ile sabitlendi).
   - Aidiyet `workout_sessions.calendar_date_key` üzerindendir (R113.3); kullanıcı tarihi override ederse set o haftaya taşınır — beklenen davranış.

3. **Unilateral kuralı.** `tracking_mode='separate'` → aynı `set_index` altındaki `left` + `right` satırları DISTINCT ile **1 set**; `bothSame` → tek `both` satırı **1 set** (R102.4). Yalnızca tek taraf loglanmışsa (örn. sağ taraf ağrı nedeniyle atlandı) yine 1 set sayılır — exposure gerçekleşmiştir — ve UI "yalnızca sol" notu gösterir; taraf bazında geçmiş `side` kolonunda korunur (R102.3). Tonaj (kg·rep): `Σ load × reps × volume_multiplier`; `separate` modunda iki tarafın toplamı, `bothSame` modunda `load × reps` (×2 **yok**). `volume_multiplier` Zod ile `1` literaline sabitlenir (`Exercise.volumeMultiplier: 1`); kolon gelecekteki farklı bir politika için vardır ve değiştirilmesi yeni ADR gerektirir.

4. **Secondary katkı ayrı, etiketli tahmindir.** `secondarySetsEstimate(muscle) = 0.5 × |{ direct set kriterini sağlayan working set : muscle ∈ exercises.secondary_muscles_json }|`. Bu değer `directSets`'e **eklenmez**; `VolumeAnalytics` çıktısında ayrı alandır, `isEstimate: true` taşır ve UI'da ayrı satırda, gri tonda, **"tahmini dolaylı katkı (×0.5)"** etiketiyle gösterilir (R106.3, R106.4, R123.4). `muscle_volume_targets` ile karşılaştırmada, `VolumeGuardrails`'de ve Day 90 raporunun ana tablosunda **kullanılmaz**. Hesap domain katmanında (`ExerciseCatalog` üzerinden, TypeScript) yapılır; `secondary_muscles_json` JSON kolon olduğu için SQL görünümü tanımlanmaz.

5. **Granülerlik ve gösterim grupları.** `VolumeAnalytics` `MuscleGroup` granülerliğinde döner (03 §3; `lats` ve `upperBack` ayrı). Spec örneğindeki "Lats/Back" gibi birleşik etiketler UI'da `MUSCLE_DISPLAY_GROUPS` sabitiyle toplanarak gösterilir; analitik katmanı bölmez, UI birleştirir. `muscle_volume_targets` `MuscleGroup` bazındadır. Liste `directSets` azalan sırada; toplam satırı = Σ direct (secondary hariç).

6. **Devam eden ve iptal edilen oturumlar.** Aktif oturumun setleri haftalık toplama girmez (görünüm `status IN ('completed','partial')`); aktif antrenman ekranı kendi oturum içi sayacını gösterir. `partial` oturumun setleri **sayılır** (yapılan iş gerçektir; R103.4/R103.5 ile tutarlı). İptal edilen oturumun setleri `discarded = 1` olduğundan hiç sayılmaz.

7. **Substitution etkisi.** Kas ataması yapılan hareketten (`set_logs.exercise_id`) gelir. Hareket-aile geçmişi (`exercise_id` / `original_exercise_id`, `exercise_relations`) ayrı bir sorudur ve hacim analitiğini etkilemez.

## Değerlendirilen alternatifler (en az 2; her biri için neden reddedildi)

| Alternatif | Neden reddedildi |
|------------|------------------|
| **A. Fractional (0.5) secondary setleri direct'e katıp tek sayı göstermek** | R106.3 yasak. "Triceps 13" hangi katsayıyla? yorumlanamaz; `max_recommended_weekly_sets` karşılaştırması bozulur; kesinlik yanılsaması (R123). |
| **B. Secondary'yi 1 tam set saymak** | R106.3 açıkça yasak. Bench 3 set → triceps +3 → yanlış "MRV aşıldı" alarmı ve yanlış `volumeHold` önerileri. |
| **C. Secondary'yi hiç göstermemek** | R106.4 ayrı gösterim ister; kullanıcı compound katkısını görmek ister; etiketli tahmin sıfır bilgiden daha yararlıdır ve dürüsttür. |
| **D. Unilateral'de tarafları ayrı set saymak (sol 3 + sağ 3 = 6)** | R102.4 yasak; "Lateral Delts 24" gibi şişme; guardrails üst sınıra yanlış çarpar. |
| **E. `bothSame` modunu kaldırıp her zaman iki satır yazmak** | R102.2 hızlı UX ister; iki satır = iki komut veya karmaşık tek komut; DISTINCT zaten iki modu eşitliyor, gereksiz karmaşıklık. |
| **F. Ana metrik olarak tonaj (kg·rep)** | R106.1/R106.2 set sayısı ister; tonaj yük türleri arasında (assisted, bodyweight, machineLevel — §101) karşılaştırılamaz; set sayısı hipertrofi dozunun literatürdeki birimidir. |
| **G. Sayımı yalnızca JS'te satır satır yapmak (görünüm yok)** | Guardrails, analitik ve rapor aynı sayıyı farklı kodla üretme riski; `v_weekly_direct_sets` tek kaynaktır ve Node SQLite testinde aynen çalışır. (Secondary için JS zorunlu: JSON kolon.) |

## Sonuçlar (olumlu / olumsuz / riskler ve azaltımlar)

**Olumlu**
- Sayı tanımı nettir ve karşılaştırılabilir; çift sayım şema düzeyinde imkânsızdır (`UNIQUE (session_exercise_id, set_index, side)` + DISTINCT).
- Tek kaynak: Progress ekranı, `VolumeGuardrails` ve Day 90 raporu aynı sayıyı gösterir.
- Test etmesi kolay: görünüm fixture ile Node'da doğrulanır.

**Olumsuz**
- Direct-only sayım compound ağırlıklı programlarda küçük kasları "az" gösterir (bench yapan kullanıcıda triceps direct = 0) → azaltım: secondary tahmin satırı ve kısa açıklama metni ("compound katkısı ayrı gösterilir").
- Hafta başlangıcı sabittir (Pazartesi); kullanıcı tercihi v1'de yok.
- `dropset`/`backoff` sayılmaz → bu setleri yoğun kullananlarda hacim düşük görünür → azaltım: UI "yalnızca working set'ler sayılır" notu.
- Tek taraf loglanmış set 1 sayılır → hafif abartı; kabul edilir, UI notu ile şeffaf.

**Riskler ve azaltımlar**

| Risk | Azaltım |
|------|---------|
| 03 `set_logs`: `set_index` yorumu ("warmup ve working ayrı sayılır") ile `UNIQUE (session_exercise_id, set_index, side)` çelişir — warmup #1 ve working #1 aynı anda var olamaz | Görünüm yalnızca `working` filtrelediği için sayım etkilenmez; ancak şema düzeltilmeli (UNIQUE'e `set_type` eklenmesi veya tek sayaç). INCONSISTENCIES'e yazıldı. |
| Seed güncellemesinde bir hareketin `primary_muscle`'ı değişirse geçmiş haftalık sayılar geriye dönük değişir | Analitik saklanmaz, türetilir; `seed_version` ile değişiklik izlenir ve seed testi `primary_muscle` değişikliğini açıkça onaylatır. |
| `secondary_muscles_json` SQL'de sorgulanamaz → JS'te tüm haftanın setleri belleğe alınır | Hafta başına set sayısı küçüktür (< 300); `ExerciseCatalog` bellek içi haritadır. |
| Kullanıcı `calendar_date_key` override'ı ile seti başka haftaya taşır | Beklenen davranış; `calendar_date_overridden = 1` UI'da ipucu olarak gösterilir. |

## Doğrulama (hangi test/kabul senaryosu bu kararı doğrular)

- **Integration (Node SQLite, aynı DDL) — `v_weekly_direct_sets`:** fixture: unilateral hareket `separate` 3 set (6 satır) + aynı hareket `bothSame` 3 set (3 satır) + bench 3 working + 2 warmup + `discarded=1` oturumda 3 set + aktif oturumda 2 set → `lateralDelts = 6`, `chest = 3`; warmup, discarded ve aktif oturum setleri 0; `triceps` direct 0.
- **Unit — `VolumeAnalytics.weekly`:** bench 3 set → `chest.directSets = 3`, `triceps.secondarySetsEstimate = 1.5` ve `isEstimate = true`, `triceps.directSets = 0`; hafta sınırı Pazartesi (FakeClock ile `calendar_date_key` Pazar ve Pazartesi kayıtları farklı haftada); `partial` oturum setleri dahil; tek taraf loglanan set = 1.
- **Unit — `VolumeGuardrails`:** `currentWeeklySets` yalnızca `directSets`'ten gelir; `secondarySetsEstimate` çağrılmaz (spy).
- **Property test:** rastgele `tracking_mode`/`side` kombinasyonlarında `directSets == COUNT(DISTINCT set_index)` ve `directSets ≤ planned_working_sets`.
- **Zod/tip:** `Exercise.volumeMultiplier` literal `1`; seed'de farklı değer → test hatası.
- **Component (RNTL) — Progress "Weekly Sets by Muscle":** satırlar `directSets` azalan; secondary satırı "tahmin" rozeti ve ayrı stil; toplam = Σ direct; `MUSCLE_DISPLAY_GROUPS` ile "Lats/Back" = `lats + upperBack`.
- **AT-06** (dolaylı): kısmi antrenman kaydı sonrası adherence doğru **ve** o oturumun working set'leri haftalık hacimde görünür.
