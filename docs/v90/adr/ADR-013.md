# ADR-013: Web hedefi — sql.js bellek içi motor, AES-GCM görüntü şifrelemesi, GitHub Pages
- **Durum:** Kabul edildi
- **Tarih:** 2026-09-13
- **İlgili gereksinimler:** R93.3, R93.4, R93.5, R93.6 (tarayıcı karşılığı), R93.7, R94.5, R94.6, R95.1, R95.4, R95.7, R116.1, R116.2, R116.3, R116.5, R118, R123; dolaylı: R91.5 (bildirim yok, sayaç formülden türer), R92.5 (`.bak` görüntüsü aynı depoda), R117.3 (`DbOpenError`). Kabul senaryoları: AT-14, AT-15, AT-16 (sql.js yolunda Node'da koşar), AT-17 (aynı fallback), AT-18 (service worker kabuğu); AT-19 web'de **kapsam dışı**.

## Bağlam

V90 tek kullanıcılı, sunucusuz, offline-first bir uygulamadır; native sürümde veri SQLCipher ile şifreli SQLite dosyasındadır ve anahtar Keychain/Keystore'dadır (ADR-002). Aynı uygulamanın **tarayıcıda** da çalışması istenir: kurulum gerektirmeden, sunucusuz, çevrimdışı ve depo herkese açık olduğu için ücretsiz GitHub Pages üzerinde (`https://<kullanıcı>.github.io/kredi-karti-takip/`). Web sürümü "hafif bir kopya" değildir: aynı şema, aynı motorlar, aynı yedek formatı; kullanıcı web'de başlayıp yedeğini Android uygulamasına taşıyabilmelidir.

Kısıtlar:
- Tarayıcıda **SQLCipher yoktur**. `expo-sqlite`'ın web gerçekleştirmesi (wa-sqlite) `SharedArrayBuffer` ister; bu da `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` yanıt başlıkları demektir. GitHub Pages **yanıt başlığı gönderemez**.
- R93.4 (dürüstlük): SQLCipher yoksa "SQLCipher" denmez. R93.7: production şifresiz sağlayıcıyla başlayamaz — web'de `isEncrypted` ancak gerçekten şifreleyen bir bileşen varsa `true` olabilir.
- R93.5/R93.6: anahtar kaynak kodda, `localStorage`'da ya da düz metin olarak hiçbir depoda bulunamaz.
- Tarayıcı depolaması (IndexedDB) **tahliye edilebilir**; aynı kaynaktaki (origin) her sekme aynı depoyu görür; hiçbir tarayıcı biyometrik kilit ya da güvenilir arka plan bildirimi sunmaz.
- R116.3 / R118: bulut senkronu, hesap, "yakında" ve analitik yoktur; web bu kuralları gevşetmez.
- Kod tabanı tektir: platform ayrımı Metro platform uzantılarıyla yapılır (`src/platform/x.ts` yerel, `x.web.ts` web; **aynı dışa aktarım adları**). `src/bootstrap/container.ts` hiçbir sağlayıcıyı import etmez; uygulama `makeProvider`'ı platformdan geçirir (`src/ui/AppProvider.tsx`).

## Karar

### 1. Motor: sql.js (SQLite → wasm), tamamen bellekte; aynı `SqliteDatabaseProvider`

```
SqliteDriver { name; supportsEncryption; encryptsAtRest?; open(path) }
  sqlJs  → web production (sql.js, bellekte)   supportsEncryption = false, encryptsAtRest = store.isEncrypted

makeSqlJsProvider({ path, store, locateFile })
  = SqliteDatabaseProvider(sqlJsDriver({ store, locateFile }), path, pragmas: ['PRAGMA foreign_keys = ON'])
```

- `src/core/db/drivers/sqlJs.ts` `SqliteDriver` portunu uygular; `src/core/db/SqlJsProvider.ts` sağlayıcıyı kurar. `keyManager` **yoktur**: `PRAGMA key` gelmez, SQLCipher taklidi yapılmaz (R93.4).
- Repository'ler, servisler ve `MigrationRunner` yine yalnızca `Db` portunu görür (R93.3); web için tek satır domain kodu değişmez.
- `DEFAULT_PRAGMAS`'ın kalanı bellek içi motorda anlamsızdır ve uygulanmaz: `journal_mode = WAL` (dosya sistemi ister), `synchronous = FULL` (fsync edecek dosya yok), `busy_timeout` (tek bağlantı).
- wasm ikilisi Metro bundle'ından değil `<base>/sql-wasm[-browser].wasm` adresinden yüklenir (`locateFile`); `scripts/copy-web-assets.mjs` `postinstall`'da paketten `public/` altına kopyalar.
- Platform sağlayıcısı `src/platform/db.web.ts` → `makeProvider(path)`; yerel karşılığı `db.ts` (expo-sqlite + SQLCipher). İki motor birbirine **sızmaz**: `scripts/check-bundle.mjs ios` web izlerini (`sqlJsDriver`, `EncryptedImageStore`, `sql-wasm`), `check-bundle.mjs web` yerel izleri (`expo-sqlite`, `ExpoSecureStore`, `WHEN_UNLOCKED_THIS_DEVICE_ONLY`) yasaklar. (`PRAGMA key` metni ortak `SqliteDatabaseProvider`'da durur ve yalnızca `keyManager` verildiğinde gönderilir; web sağlayıcısı anahtarsızdır — bu yüzden yasak listesinde değildir.)

### 2. Dayanıklılık: her COMMIT sonrası görüntünün tamamı `ImageStore`'a yazılır

```
ImageStore { load(name); save(name, bytes); remove; exists; size; freeSpace; readonly isEncrypted }
  InMemoryImageStore   → test (şifrelemez, isEncrypted = false)
  IdbImageStore        → web, IndexedDB "images" deposu (düz; isEncrypted = false)
  EncryptedImageStore  → sarmalayıcı: save şifreler, load çözer (isEncrypted = true)
```

- `SqliteDatabaseProvider` her `COMMIT`'ten ve transaction dışı her yazmadan sonra `conn.persist()` çağırır; sql.js sürücüsü `db.export()` ile görüntüyü çıkarır ve `store.save(path, bytes)` ile depoya yazar. Dosya tabanlı sürücülerde `persist` yoktur (SQLite zaten yazdı).
- Adlar dosya yolu değil **depo anahtarıdır** (`'v90.sqlite'`, `'v90.sqlite.v3.bak'`, `'v90.import.sqlite'`). Migration yedeği `ImageFileStore.copy` = `load` + `save`; yani `.bak` de aynı depoda, aynı anahtarla şifreli durur (R92.5).
- **Maliyet:** her commit'te görüntünün tamamı yazılır. V90 verisi küçüktür (onlarca KB – birkaç MB); set başına tek küçük transaction vardır (02 §7.1). IndexedDB'de tek anahtara tek `put` tek transaction'dır: yarım görüntü kalmaz (`ImageStore.save` atomiklik sözleşmesi).
- `db.export()` dosyayı kapatıp yeniden açar ve bağlantı düzeyi PRAGMA'ları sıfırlar. Sürücü `PRAGMA x = y` biçimindeki ifadeleri ada göre kaydeder ve her export'tan sonra **depo yazımından önce** yeniden uygular (`foreign_keys` kapalı kalmasın); dosyada saklanan PRAGMA'lar (`user_version`, `journal_mode`…) bu listeye alınmaz — geri alınmış bir transaction'ın `user_version` yazımı yeniden uygulansaydı şema sürümü yanlış ilerlerdi (R92.6).
- Kaybolabilecek tek şey henüz `COMMIT` edilmemiş transaction'dır — SQLite'ta da kaybolurdu. Yazma bitmeden sekme kapanırsa **son** transaction kaybolabilir; kullanıcıya "kesin" güvence verilmez (R123).

### 3. Şifreleme: `EncryptedImageStore`, AES-GCM-256 (WebCrypto); bu SQLCipher DEĞİLDİR

```
görüntü biçimi:  "V90E" (4 bayt) | 0x01 sürüm | IV (12 rastgele bayt, her yazımda yeni) | AES-GCM şifreli metin (+ etiket)
```

- `src/core/db/EncryptedImageStore.ts` düz depoyu sarar: düz depo yalnızca şifreli bayt görür, **hiçbir zaman** düz veritabanı görmez. Web'de bileşim `src/platform/web/stores.ts`: `new EncryptedImageStore(new IdbImageStore(), IdbKeyProvider)`.
- `isEncrypted` **yalnızca** sarmalayıcının beyanından türer: `sqlJsDriver.encryptsAtRest = store.isEncrypted` → `SqliteDatabaseProvider.isEncrypted = keyManager != null || driver.encryptsAtRest === true`. Düz depo `false` der ve yalan söylemez; `assertEncryptedProviderInProduction` bu bayrağa bakar (R93.7).
- Yanlış anahtar / bozuk görüntü → `DbOpenError` ("veritabanı görüntüsü bu anahtarla açılamadı"); hata metnine anahtar da görüntü de sızmaz (R93.5).
- **Dürüstlük (R93.4):** SQLite düz bellekte (wasm yığını) çalışır; şifreli olan yalnızca dinlenirken depoya yazılan görüntüdür. UI metinleri bunu olduğu gibi anlatır ("AES-GCM ile şifreli görüntü", "çıkarılamaz anahtar"); web için hiçbir metinde "SQLCipher" geçmez (06 B.20 kopya kuralı). Web bundle denetimi `AES-GCM`, `V90E`, `v90.web.dbkey` izlerini **ister** ki denetim boş koşmasın.

### 4. Anahtar: çıkarılamaz `CryptoKey`, IndexedDB `"keys"` deposunda `"v90.web.dbkey"`

```
IdbKeyProvider.getOrCreateKey():
  idbGet('keys', 'v90.web.dbkey')
  ?? crypto.subtle.generateKey({ name: 'AES-GCM', length: 256 }, /* extractable */ false, ['encrypt', 'decrypt'])
     → idbAdd('keys', 'v90.web.dbkey', key)      // add, put değil: iki sekme yarışırsa ikincisi ilkinin anahtarını okur
```

- `src/platform/web/keyProvider.ts` `ImageKeyProvider` portunu uygular. `CryptoKey` yapısal klonlanabilir; tarayıcı nesneyi saklar, baytlarını JS'e **hiçbir zaman** vermez: kaynak kodda, normal depolamada, log'da, yedekte anahtar yoktur (R93.5, R93.6).
- **Güven sınırı, açıkça:** aynı kaynakta (origin) çalışan her script bu anahtarı *kullanabilir* (çözemez ama çözdürebilir). Bu, native'de Keychain'in uygulama sürecine verdiği güvenle aynıdır — orada da uygulamanın kendi kodu anahtarı okuyabilir. Web'de ek varsayım şudur: kaynağa yabancı script girmez (harici script yüklenmez, analitik yoktur — R118). Cihaz düzeyi koruma (Keystore donanımı) yoktur; bu bilinçli bir kabuldür ve UI "güvenli" gibi mutlak bir iddia yazmaz (R123).
- WebCrypto yalnızca güvenli bağlamda (https / localhost) vardır; değilse açılış `DbOpenError` ile durur, anahtar üretilmez.
- Parola türevi anahtar yoktur (ADR-002 alternatif D ile aynı gerekçe: hızlı antrenman UX'i, unutulan parola = kayıp). `destroy()` "Tüm verimi sil" akışı içindir: anahtar gidince şifreli görüntü kalıcı olarak açılamaz.
- **Anahtar kaybı = veri kaybı.** Kullanıcı site verisini temizlerse görüntü ve anahtar birlikte gider; uygulama ilk açılış gibi başlar ve tek yol indirilmiş yedek ZIP'idir (06 B.20 "Depo silindi").

### 5. Tarayıcı sınırları: tahliye, sekme kilidi

- **Tahliye:** `requestPersistentStorage()` (`src/platform/storage.web.ts`) bootstrap'tan **önce** `navigator.storage.persist()` ister; sonuç (`granted | denied | unsupported`) yalnızca Ayarlar > Web sürümü'nde gösterilir, açılış engellenmez. `denied`/`unsupported` durumunda metin "düzenli yedek al" der; aylık yedek hatırlatması web'de de açıktır. `storageEstimate()` tarayıcının tahminidir, "kesin" gösterilmez (R123).
- **Sekme kilidi:** sql.js görüntüsünü iki sekme açsa her biri diğerinin yazdığını ezerdi. `src/platform/web/tabLock.ts` Web Locks API ile `"v90.db"` kilidini sekme ömrü boyunca tutar (`acquireTabLock`, `ifAvailable: true`); ikinci sekme `DbOpenError("uygulama başka bir sekmede açık — önce onu kapat")` ile durur, veri bozulmaz. Başarısızlık önbelleğe alınmaz: diğer sekme kapatılıp "Yeniden dene" denince yeni istek yapılır. Web Locks yoksa (eski tarayıcı) kilit atlanır — tek sekmede sorun yoktur.
- IndexedDB `versionchange`/`close` olaylarında bağlantı bırakılır ve sonraki çağrı yeniden açar; başarısız açılış önbelleğe alınmaz.

### 6. Yedek taşınabilirliği: web ↔ Android aynı ZIP

- Format değişmez (ADR-005): `manifest.json`, `data.json`, `photos/`. Web'de dışa aktarılan ZIP Android uygulamasında içe aktarılır ve tersi.
- **Export:** `deliverExport` (`exportFile.web.ts`) ZIP'i `Blob` + `blob:` URL ile tarayıcı indirmesine verir (`'downloaded'`); sunucuya hiçbir şey gitmez. ZIP şifresizdir (02 §12.2) ve ekran bunu söyler.
- **Import:** tarayıcı dosya seçici; `readPickedBytes` (`pickedFile.web.ts`) `blob:`/`data:` URI'yi `fetch` ile okur; seçilen dosyaya dokunulmaz (R116.2). Staging → canlı değişimi (02 §12.3 adım 6) `PlatformBlobStore` (`blobs.web.ts`) üzerinden yapılır; `.sqlite` sonlu düz adlar şifreli görüntü deposuna yönlendirilir ki değişim aynı depoda, aynı anahtarla olsun.
- **Geri alma penceresi:** `restorePoint.web.ts` kaydı IndexedDB `"meta"` deposunda tutar; DB görüntüsünün içinde tutulamaz (import görüntüyü değiştirir), yerelde sidecar JSON'un karşılığıdır.
- **Fotoğraflar:** IndexedDB `"blobs"` deposunda `photos/<file_name>` anahtarıyla (`PrefixBlobStore` üzerinden `IdbKvStore`); görüntüleme için `resolvePhotoUris` (`photoUri.web.ts`) `blob:` URL üretir, listeden düşenleri serbest bırakır. Galeriye yazılmaz, sunucuya gitmez (R116.1–R116.3).

### 7. Barındırma ve çevrimdışı kabuk: GitHub Pages + service worker

- Alt yol: export anında `V90_WEB_BASE_URL=/kredi-karti-takip` → `app.config.ts` `experiments.baseUrl` → çalışma zamanında `process.env.EXPO_BASE_URL` (expo-router okur; `db.web.ts` ve `serviceWorker.web.ts` aynı kökü kullanır).
- Çıktı: `expo export --platform web` (`web.output: 'single'`, SPA) → `scripts/web-postexport.mjs` `404.html` (= `index.html`, Pages derin bağlantıları SPA'ya düşürür), `manifest.webmanifest` (ana ekrana ekle), `<head>` ekleri ve `sw.js` üretir.
- `sw.js` dist'teki **her** dosyayı önbelleğe alan, önbellek-öncelikli bir kabuktur; önbellek adı içerik listesinden türer, `activate` eski `v90-*` önbelleklerini siler; çapraz kaynak (örn. YouTube küçük resmi) asla önbelleğe alınmaz. `registerServiceWorker()` uygulama hazır olduktan sonra **bir kez** çağrılır; `__DEV__`'de kaydedilmez (Metro sıcak yenilemesiyle çakışır); kayıt başarısızlığı uygulamayı düşürmez (02 §2.2, AT-18).
- Yayın: `.github/workflows/v90-web.yml` (`npm run export:web` → `actions/configure-pages` `enablement: true` → `deploy-pages`). Android APK ise `v90-build-android.yml` ile GitHub Actions'ta `expo prebuild` + `gradle assembleRelease` olarak üretilir (EAS hesabı gerekmez; ADR-002 Karar 3'ün Development Build zorunluluğu değişmez, yalnızca derleme yeri değişir).

## Sonuçlar

**Olumlu**
- Aynı domain kodu, aynı migration'lar, aynı seed ve aynı yedek formatı tarayıcıda çalışır; web'de başlayan kullanıcı ZIP'ini Android'e taşıyabilir.
- Şifreli yol Node'da gerçekten koşar (`test/sqlJs.test.ts`: sql.js + `EncryptedImageStore`); "kod doğru görünüyor" ile yetinilmez.
- Anahtar hiçbir zaman JS'in eline geçmez; kaynakta, düz depoda, log'da ve yedekte bulunmaz.
- Barındırma ücretsiz ve yapılandırmasızdır; çevrimdışı açılış service worker kabuğuyla sağlanır.
- Yerel ve web motorları birbirine sızmaz; iki bundle denetimi bunu her CI koşusunda kanıtlar.

**Olumsuz**
- Her commit'te tüm görüntü yazılır; veri büyürse (yıllarca kayıt, çok sayıda büyük fotoğraf DB'de değil ama görüntü yine büyür) commit gecikmesi artar. Eşik izlenir; gerekirse sayfa düzeyi VFS'ye geçiş `ImageStore` portunun arkasında yapılır.
- Bellek içi motor: sekme çökerse ya da kapanırsa yalnızca son commit edilmemiş transaction gider, ama depo yazımı bitmeden kapanan sekmede **son** commit de kaybolabilir (R123: "kesin" denmez).
- Tarayıcı depoyu tahliye edebilir; anahtar da gider; kullanıcı yedek almadıysa veri gider.
- Tek sekme kısıtı.
- Biyometrik kilit, bildirim ve ekran görüntüsü engeli yoktur; bunlar açıkça yazılır.
- Web'de cihaz düzeyi anahtar koruması (Keystore donanımı) yoktur; güven sınırı kaynak (origin) düzeyindedir.

**Riskler ve azaltımlar**
- *Depo tahliyesi.* → `navigator.storage.persist()` bootstrap öncesi istenir; sonuç Ayarlar'da görünür; yedek hatırlatması; Yedekleme ekranındaki web ipucu "tarayıcı verisi silinirse kayıtlar yalnızca bu dosyadan geri gelir" der.
- *İki sekme aynı anahtarı üretir.* → `idbAdd` (put değil): ikinci sekme `ConstraintError` alır ve ilkinin anahtarını okur.
- *İki sekme aynı görüntüyü ezer.* → Web Locks `"v90.db"` kilidi; ikinci sekme açılmaz.
- *`db.export()` sonrası `foreign_keys` kapalı kalır.* → Yapışan PRAGMA'lar depo yazımından önce yeniden uygulanır; test bunu doğrular.
- *Geri alınmış transaction'ın `user_version` yazımı export sonrası yeniden uygulanır.* → Dosyada saklanan PRAGMA'lar yapışan listeye alınmaz.
- *Yanlış wasm ikilisi yanlış glue ile açılır.* → `copy-web-assets.mjs` iki ikiliyi de (`sql-wasm.wasm`, `sql-wasm-browser.wasm`) `public/` altına kopyalar; `v90-web.yml` çıktıda varlığını denetler.
- *Web bundle'ına yerel motor, yerel bundle'a web motoru sızar.* → `check-bundle.mjs ios|web` yasak/zorunlu iz listeleri; CI'da her push'ta.
- *GitHub Pages ilk dağıtımda kapalıdır.* → `configure-pages` `enablement: true`; başarısız olursa depo Ayarlar → Pages → Source "GitHub Actions" bir kez elle seçilir.
- *Service worker eski kabuğu sunar.* → Önbellek adı içerik listesinden türer; yeni export yeni ad, `activate` eskileri siler.
- *Güvensiz bağlam (http).* → WebCrypto yoktur; açılış açık hatayla durur, anahtar üretilmez, veri düz yazılmaz.
